# Navigation & Pipeline Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the InTalent sidebar compact (collapsible sections, icon rail, 13 items), fold Notes and Ultra Upload into their parent pages, add a "Trang tuyển dụng" page, and redesign the Pipeline (compact cards, header bar, list view, collapsible Hired/Rejected).

**Architecture:** Changes stay inside the existing React app (`app/`) on branch `feat/recruitment-app`. Pure helpers go in `app/src/domain/`, and UI changes go in the existing feature folders. Fixture mode (`?fixture=mockup`) keeps today's rendering untouched.

**Tech Stack:** Vite 6, React 18, TypeScript 5, React Router 6, Zustand 4, @dnd-kit/core, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-17-intalent-nav-pipeline-redesign-design.md` (base spec: `docs/superpowers/specs/2026-11-16-intalent-recruitment-app-design.md`)

## Global Constraints

- Fixture mode (`?fixture=mockup`) renders the old sidebar and the old Candidate Pool / Upload pages pixel-identically; `npm run fidelity` must still exit 0 (≤ 0.5%).
- New UI uses only classes in `app/public/assets/app.css` or those generated by the Tailwind supplement (preflight off).
- All new strings go through `useT()` with en + vi keys (vi is typed Record, so tsc fails on a missing key).
- Desktop 1440×900. The existing 244 tests stay green, and `npm run build` stays clean.
- Nav fold state lives in `localStorage` key `intalent-ui-nav`, outside the demo store, so Reset demo doesn't touch it. Every read and write is wrapped in try/catch.
- Groups (normal mode): Dashboard · TUYỂN DỤNG (Jobs, Pipeline, Campaigns, Trang tuyển dụng) · TALENT POOL (Ứng viên, Upload CV, AI Search) · JD (JD Management, JD Matching) · CÀI ĐẶT (Taxonomy, System Config, Users, CV theo TA). CÀI ĐẶT is folded by default.
- Published-jobs route: `/published`. Its icon is `public`. List-view page size is 20.
- Pipeline drag & drop, keyboard moves, the reject reason and the drawer behave as today.

## Review Focus

1. A group that holds the current route must be open even if the user folded it. → Task 1 test `group with active route is forced open`.
2. Corrupt or blocked `localStorage` for `intalent-ui-nav` must not crash the sidebar; it falls back to the defaults. → Task 1 test `invalid stored nav state falls back to defaults`.
3. Old links `/notes` and `/upload-ultra` keep working: `/notes` → `/candidates?tab=notes`, and `/upload-ultra` still renders Ultra in normal mode. → Task 2 tests.
4. Dropping on a collapsed Rejected strip still asks for a reason; dropping on a collapsed Hired strip moves the card. → Task 5 test `collapsed rejected strip still requires reason`.
5. Search and the source filter that leave zero cards show an empty message in both views, not an empty board. → Task 5 test `filters with no match show empty message`.

### Task 5: Pipeline list view and collapsible end columns

**Files:**
- Create: `app/src/features/pipeline/PipelineList.tsx`, `PipelineList.test.tsx`
- Modify: `Board.tsx`, `Column.tsx`, `PipelinePage.tsx`, `app/src/features/jobs/JobDetailPage.tsx` (embedded board uses the same header and views), i18n files

**Interfaces:**
- Consumes `filterApplications`, `PipelineHeader`, `handleDrop`, `RejectDialog`, and `ApplicationDrawer` from earlier tasks/today.
- `PipelineList({ job, apps, candidates, onOpen, onMove })` is a sortable table. Columns: Ứng viên, Vòng (stage chip), Nguồn, Ngày trong vòng, Điểm, Ngày thêm. It sorts by any column (asc/desc toggle) with stage order as default, pages at 20 rows (Pagination with translated labels), opens the drawer on row click, and has a per-row "Chuyển sang…" menu (reuse `MoveToMenu`) that goes through `handleDrop`, so rejected still asks for a reason.
- `Column` gets `collapsed?: boolean; onToggleCollapse?: () => void`. Collapsed renders a narrow vertical strip (`w-12`) with the rotated stage name and count, and it stays a dnd-kit droppable with the same stage id.
- Default collapse: Hired and Rejected start collapsed when the active stages (new..offer) hold more than 3 applications in total. The user toggle overrides this for the session.
- Empty after filters: both views show `pipeline.filter.noMatch` ("No candidates match" / "Không có ứng viên phù hợp").
- **Move note:** `RejectDialog` becomes `MoveDialog({ open, name, to: Stage, onCancel, onConfirm(note: string) })`, titled "Chuyển sang {stage}" / "Move to {stage}". The note textarea is optional, but required (trimmed non-empty) when `to === 'rejected'`, which keeps today's reject wording. `handleDrop` returns `'needs_note'` for any real move, replacing `'needs_reason'`; `'none'` stays for no-ops. A new `commitMove(appId, to, note, by)` calls `moveStage(appId, to, by, reason?, note?)`. The store's `moveStage` gains an optional `note` saved on the new history entry `{stage, at, by, note?}`, and `rejectedReason` = note when `to==='rejected'`. Every move path uses it: drag, keyboard, the card menu, the list-row menu and the drawer's "Move to…". `ApplicationDrawer` stage history shows `note` under each entry.
